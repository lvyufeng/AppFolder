## 它是怎么做到「点一下直开」的

系统动作采用 iOS 27 的 `RunSystemShortcutIntent`：**由系统执行，不经过 AppFolder、不依赖 URL scheme**。用户可以在「编辑小组件」面板中选择打开已安装 App、运行 App Shortcut、自定义快捷指令或系统动作。实际动作必须由用户在系统面板中选择；AppFolder 不枚举已安装 App，也不替用户指定系统动作。网站格子使用独立的网址入口，无需额外配置同名系统动作。联系人专用格子则先进入 AppFolder，再交给系统通信 App 处理，启动路径与系统动作不同。

**App 内提供「我的分组」、动作资料库、待添加网页、配置检查、离线交互预览、添加教程、图标工作室与备份恢复**。在「我的分组」中可以保存多个布局，批量添加命名动作、添加文件夹和空位，重排内容或在文件夹之间移动；每个分组最多 200 项、文件夹最多嵌套四层。分组名称、动作名称和文件夹树保存在 App Group 共享容器中。保存后，仍需在系统「编辑小组件」面板的「分组布局」中选择分组，并在「动作」中选择实际要运行的动作；网格、布局密度、名称显示、图标大小、底板、颜色和返回按钮样式可随分组保存；在系统面板开启「使用分组外观」即可应用，关闭时保留组件自己的外观。这个开关默认关闭，已有组件不会自动改样式。系统动作由 WidgetKit 持有，分组文件不保存系统动作本身。

动作资料库把小组件曾记录的名称、已保存分组中的真实动作名称、图标／手动匹配记录及手工记录统一展示，可搜索名称或标签，按标签分类，归档或批量加入分组。标签与归档只是本地整理资料，不修改动作绑定、分组节点或图标；它不代表 App 已安装或系统动作已配置。最多保存 4096 条记录，每条最多 16 个标签、每个标签最多 32 字符；名称采用与动作绑定相同的大小写／Unicode 规范化身份。整理先修改草稿，只有「保存整理」才写入；取消不写。显式手工无标签记录仍保留，清除不存在的标签或取消归档不会意外创建空记录。选择器按选择顺序加入，切换筛选或刷新保留选择，超过分组 200 项上限时不部分添加。

小组件按名称把分组中的动作与当前配置的系统动作对应起来，匹配时忽略首尾空白和大小写。只有唯一的同名动作会成为可运行的格子；缺失或同名冲突会提示重新配置，不会按位置猜测目标。动作可单独设置显示名称：例如将「地图」显示为「出行」，绑定与图标仍使用原来的动作名称；只有「更换绑定动作」会改变匹配目标。清空显示名称会恢复原动作名。分组预览可以点开文件夹和翻页，但不会运行动作或替你修改桌面配置。打开 App 时还会请小组件收回展开态。

网站格子保存标题和绝对 HTTP(S) 网址，可以与系统动作混排、放进文件夹；纯网站分组不需要系统动作。输入省略协议时补全 HTTPS，保存和读取时严格校验网址，拒绝凭据、控制字符、无效转义或端口，网址上限为 2048 UTF-8 字节。只有点击「测试链接」或网站图块才按所选方式打开网址；输入、布局预览和导入不会访问网站。默认使用地球图标，也可为每个网站格子独立设置普通/深色照片、符号、文字或日期样式；图标属于该格子，不按标题共享。文件夹缩略图按内容顺序混合展示动作、网站或联系人，默认 2×2（最多四项），也可为每个文件夹单独选择 3×3（最多九项）。模型、备份、正式编辑界面和组件已接入并构建通过；网站编辑、单组分享导入和小号桌面网站打开已完成下述实测，原生分享弹窗的最终复验也已通过，具体边界见「目前状态」。

每个网站可以选择系统默认、App 内浏览、Chrome 或 Firefox。旧网站及系统默认选择保持原来的 `OpenWebsiteIntent` 直开；其他选择通过仅含分组/项目 ID 的 AppFolder 本地路由交接，宿主在打开前重读保存记录。App 内浏览直接呈现系统 `SFSafariViewController` 完整模态页面；正常浏览可执行站点脚本，与下述只读元数据获取不同。第三方浏览器未安装或无法打开时明确提示，只有再次点按才使用系统默认方式，不静默改选。排队、过期或已进后台的路由不会稍后自动打开；已呈现的 Safari 在临时切后台时保持，返回不会重复打开。

浏览器选择、名称、网址和图标属于一次分组草稿编辑，支持现有撤销、复制及 v14 备份；不更改保存的原网址。Chrome 按其官方协议只替换传输 scheme；Firefox 使用官方单个 `url` 参数，但其接收端可能重新编码查询参数，复杂或签名链接建议使用系统默认。当前未加入 Edge 或自定义浏览器模板，不能将现有选项写成已完整覆盖竞品所有浏览器能力。实际系统交接与界面保存的验收范围见后续记录。

## 核心结论

1. 普通宿主深链接与系统动作是不同入口；本项目用 `RunSystemShortcutIntent` 执行用户在系统面板选择的动作，不经宿主中转。
2. 打开已安装 App 的历史实验有三条：经宿主 App 中转（有闪烁）、`https://` 通用链接（当时覆盖率只有 6/60）、iOS 27 的 `RunSystemShortcutIntent`（由用户手选、系统执行）。本仓库的 App 动作保留第三条；新增网站格子用于打开用户保存的网址，不替代 App 动作匹配。
3. iOS **没有**任何公开 API 能枚举已安装 App。小组件只拿得到一个显示名，图标要靠名字去 App Store 反查、下载后缓存在 App Group 里。

## 目录结构

```
AppFolder/              宿主 App（SwiftUI，分组编辑、配置检查、备份恢复、预览、引导、图标工作室与隐私政策）
AppFolderWidget/        widget 扩展（主屏直开与锁屏启动）
AppFolderShareExtension/ 网页分享扩展（只接收网址到本地待添加列表）

Config/                 Info.plist、entitlements
docs/research/          调研文档
```

## 开发

```bash
# 快速类型检查（比完整构建快得多）
swift build --package-path Packages/AppFolderKit

# 跑共享 package 的测试
swift test --package-path Packages/AppFolderKit

# 构建 App
xcodebuild -project AppFolder.xcodeproj -scheme AppFolder \
  -sdk iphoneos -destination 'generic/platform=iOS' build

# 模拟器交互验证要保留签名，以创建真正的 App Group 共享容器
xcodebuild -project AppFolder.xcodeproj -scheme AppFolder \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- build
```

`CODE_SIGNING_ALLOWED=NO` 只适合编译检查，不能据此证明图标保存或组件共享可用。模拟器安装后可用 `simctl get_app_container <设备 ID> com.lvyufeng.appfolder groups` 确认共享容器；App 与扩展拿不到容器时应明确报告不可用。

- Xcode 27.0+ / Swift 6.4（本仓库用 Swift 6 语言模式，严格并发）
- 当前最低部署目标 iOS 27.0（本版依赖 iOS 27 的 `RunSystemShortcutIntent`，未实现更低版本的替代执行方式）

> ⚠️ App Group 是 App、widget 与网页分享扩展的本地共享通道，保存分组、图标与封面资源、待添加网页及组件导航状态都依赖它。容器不可用时，这些共享数据功能无法正常工作，应按界面提示检查配置，不能只把影响理解为「收回展开」请求无法传递。
